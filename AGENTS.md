# Рабочее пространство ревьюеров

Проверяем только PR #68 команды toyota-skyline. Версия записана в REVIEW_SCOPE.json.

## Обязательное разделение работы и результатов

Этот репозиторий нужен для совместного исследования и независимого воспроизведения дефектов на неизменной сданной версии. Правило для людей и агентов и таблица размещения материалов находятся в начале [README.md](README.md#главное-правило-что-куда-писать).

- `source/` — неизменяемый объект проверки. Не добавляй туда наши тесты, отчёты или исправления и не обновляй SHA подмодуля.
- Гипотезы, распределение работы и обсуждения веди в Issues рабочего репозитория; создание внешних записей выполняй только по явному поручению пользователя.
- Воспроизведения размещай в `repro/<идентификатор>/`, очищенные доказательства — в `evidence/<идентификатор>/`, подтверждённые замечания — в `findings/<идентификатор>.md` по шаблону. Непроверенные гипотезы не помещай в подтверждённые находки.
- Изменения материалов ревью оформляй ветками `review/<область>` и внутренними PR этого репозитория. Их не переноси в ветку сдачи чужой команды.
- Итог для зачёта — GitHub Review в https://github.com/markpolyak/lab_grader_web/pull/68. Внутренние Issues, PR и отчёты его не заменяют. Публикуй только по явному поручению пользователя.
- Итоговое замечание должно быть воспроизводимо без доступа к приватному рабочему репозиторию: включай минимальный тест либо шаги, ожидаемый и фактический результат и существенный вывод непосредственно в review.

## Проверки и границы работы

- Перед проверками запускай `python3 scripts/verify_baseline.py`.
- Не исправляй приложение и не меняй SHA подмодуля source. Тесты, скрипты, отчёты и конфигурацию ревью размещай вне source.
- Не переноси изменения в решение sensei-mcp и не используй его закрытые отчёты.
- Исследуй требования, отделяй дефекты PR от унаследованных ошибок и проблем окружения.
- Подтверждай каждый дефект падающим тестом либо воспроизводимым сценарием с ожидаемым и фактическим результатом.
- Для находки указывай SHA, исходные строки, основание ожидаемого поведения, команду, вывод и ограничения доказательства.
- Не называй гипотезы подтверждёнными дефектами. Не выдавай успешный тест, проверяющий наличие бага, за падающий регрессионный тест.
- Используй синтетические данные, fake-клиенты и изолированные окружения. Не меняй боевые таблицы и чужие сервисы.
- Не коммить секреты, реальные персональные данные и необработанные логи с ними.
- Сохраняй чужие изменения. Коммиты делай только в рабочем репозитории ревью и только в рамках текущей задачи.
- Публикация замечаний в исходный PR, отправка приглашений и изменение доступа требуют явного поручения пользователя.
