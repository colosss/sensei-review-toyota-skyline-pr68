# Входящие наблюдения коллеги

Источник: сообщение пользователя и скриншот интерфейса, полученные 11.11.2026. По словам пользователя, наблюдения сделаны коллегой накануне. Исходные команды, данные, версия и окружение не переданы. **Все восемь пунктов пока имеют статус «гипотеза; независимо не воспроизведено».** В `findings/` они не перенесены.

На скриншоте показаны успешное обновление позиции, «позиция 2 из 2», ввод сдвига 1000, три строки списка с номерами 2, 1, 1, две одинаковые подписи Иванова и одна подпись Петровой. Это описание видимого UI, а не доказательство трёх записей одной очереди или двух записей одного пользователя. Скриншот в репозиторий не добавлен: доступен только во входящем сообщении.

Для всех проверок: сначала baseline; синтетические пользователи и хранилище; фиксированные курс, группа, лабораторная, дата и время. После воспроизведения записать SHA, команды, вывод, требование и сравнение с базой PR. Статусы: гипотеза → воспроизведено → независимо подтверждено → готово к review; альтернативы — опровергнуто / унаследовано / проблема окружения / заблокировано (с причиной). Обновляет реестр координатор после получения доказательств.

## C01 — «Локальная разработка: нет proxy в nginx»

- Проверить штатный путь по `source/docs/DEVELOPMENT.md`, Compose, `nginx.conf`, сборочную настройку API URL и запросы браузера. Отдельно проверить уже отмеченное в AGENT_TASK несовпадение портов `8080:80` и `listen 8080`.
- Критерий: описанный способ запуска должен позволять UI обращаться к API. Отсутствие proxy само по себе не ошибка, если предусмотрен рабочий прямой URL/CORS.
- Доказательство: точная конфигурация запуска, адреса UI/API, HTTP-ошибки и browser console/network; сравнение тех же файлов с базой. Не смешивать проблему порта и маршрутизацию API без установления причины. Исправленный runtime ревью не доказывает штатную работоспособность.

## C02 — «Можно записаться дважды до сдачи первой и на несколько лаб»

- Проверить последовательно и конкурентно: тот же пользователь + та же лабораторная; тот же пользователь + другая лабораторная; другая группа/курс; после выхода, сдачи и смены дня. Использовать стабильный ID/GitHub login, а не только ФИО.
- Найти правило уникальности и допустимую область очереди. Запись на разные лабораторные может быть разрешена; не объявлять нарушением без основания.
- Доказательство: запросы и ответы, ключи записей, состояния до/после и нарушенный инвариант. Повторные клики UI отделить от обхода проверки в API.

## C03 — «Неэффективная проверка через Git»

- Формулировка неоднозначна: неизвестно, речь о скорости, количестве API-запросов или обходе проверки CI. Сначала изучить контракт проверки репозитория/CI; сохранять эти трактовки раздельно.
- Проверить соответствие результата CI проверяемому SHA/ветке/обязательным jobs, отсутствие или незавершённость проверок; отдельно измерить число запросов и поведение при таймаутах/квоте через fake-клиент.
- Критерий: ложный допуск/отказ либо воспроизводимый отказ при поддерживаемой нагрузке. Субъективное «медленно» или выбор GitHub как интеграции не являются доказательством. Не выполнять нагрузочную проверку чужих сервисов.

## C04 — «Авторизация бессмысленна: можно ввести данные другого человека»

- Две локальные сессии A/B и пользователь без сессии. Проверить регистрацию/привязку личности, запись, выход и сдвиг от имени B из сессии A; прямой API отдельно от UI. Зафиксировать, какие поля взяты из подписанной сессии, а какие из тела запроса.
- Критерий: неразрешённое действие над чужой записью/привязкой по контракту идентификации. Сам ввод чужого ФИО в форме ещё не доказывает обход полномочий. Проверить, не унаследована ли публичная регистрация из базы и меняет ли PR границы доверия.
- Доказательство: минимальные обезличенные HTTP-запросы, состояние B до/после и источник требования. Не сохранять токены/настоящие cookie.

## C05 — «Запись подтверждена, но появляется в списке позднее»

- Сопоставить время ответа мутации, немедленное чтение API, видимый список, ручное обновление и повторное чтение после документированного TTL. Проверить фильтры курса/группы/лабы/дня.
- Критерий зависит от обещанного контракта согласованности; измерить длительность и последствия. Проверить инвалидацию кэша и возможность повторной записи из-за отсутствия строки.
- Доказательство: временная шкала, ответы API и UI до/после. Не принимать произвольный sleep за детерминированное доказательство; fake clock/events предпочтительны. Реальные браузерные задержки описать честно.

## C06 — «Нумерация очереди»

- На синтетических A/B/C проверить одну и ту же очередь до/после входа, выхода, shift и смены статуса; сравнить порядок хранения, API и UI. Определить, отображается абсолютная позиция или позиция внутри группы/лабы.
- Критерий: дубли/разрывы/порядок, противоречащие установленному контракту. Номера 2, 1, 1 на скриншоте — повод проверить область сортировки, а не готовый вывод о повреждении данных.
- Доказательство: идентификаторы записей, состав и область очереди, ожидаемое/фактическое отображение. Отделить ошибку отображения от ошибки изменения порядка.

## C07 — «Администратору показывают очередь, но ничего нельзя сделать»

- Найти требование к просмотру/управлению преподавателем: смена статуса, вызов, завершение, закрытие дня. Войти администратором, проверить предусмотренные экран и API, сопоставить с работой через таблицу.
- Критерий: недоступна обязательная операция в поддерживаемом сценарии. Read-only экран и предпочтение управлять через UI сами по себе не дефект, если управление предусмотрено в таблице.
- Доказательство: конкретное требование и последовательность, на которой нужное действие невозможно; различить отсутствие функции и неверные полномочия/маршрут.

## C08 — «Сдвиг странный, возможно из-за двух Ивановых»

- Повторить на разных ФИО и на одинаковых ФИО с различными стабильными ID; затем на повторной записи одного ID. Проверить сдвиги 0, 1, длина очереди, 1000, отрицательное и нецелое значение непосредственно в API; UI может ограничивать ввод.
- Определить семантику «назад на N», допустимые границы и область пересчёта. Слишком большой сдвиг может корректно ограничиваться концом очереди.
- Доказательство: ID выбранной записи, список до/после, ответ API и затронутые строки. Нельзя приписывать причину одинаковым ФИО без сравнения; проверить связь с C02/C06, не создавать три замечания об одной причине.

## Перед включением в review

Координатор проверяет независимое воспроизведение, основание ожидания, отношение к diff PR, воздействие, возражения и отсутствие дублей. Если подтвердится только часть исходного сообщения, формулирует замечание ровно об этой части. Новые гипотезы добавляются отдельно с источником; количество входящих пунктов не задаёт план по количеству находок.
