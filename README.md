## Начать работу

После создания репозитория на GitHub:

```bash
git clone --recurse-submodules https://github.com/colosss/sensei-review-toyota-skyline-pr68.git
cd sensei-review-toyota-skyline-pr68
python3 scripts/verify_baseline.py
git switch -c review/queue-registration
```

Если уже склонировали без подмодулей: `git submodule update --init --recursive`.

- `source/` — проверяемое приложение; [инструкция разработчика](source/docs/DEVELOPMENT.md), [описание проекта](source/docs/PROJECT_DESCRIPTION.md).
- `repro/` — наши тесты и скрипты воспроизведения.
- `findings/` — подтверждённые дефекты по шаблону `TEMPLATE.md`.
- `evidence/` — небольшие очищенные логи и скриншоты.
- `REVIEW_SCOPE.json` — SHA и ссылки для воспроизводимости.

Установка зависимостей и запуск приложения выполняются по документации `source/` в отдельном окружении. Реквизиты тестовых интеграций каждый участник настраивает локально. Этот репозиторий не содержит запущенного приложения или готовых результатов проверки.

## Как работаем командой

1. Создайте Issue в этом репозитории с областью проверки и назначьте ответственного. Гипотезу обозначайте явно.
2. Создайте ветку `review/<область>`, добавляйте свои файлы вне `source/`.
3. Зафиксируйте условия, команду запуска, ожидаемый результат, фактический результат и основание из требований. Для каждого теста укажите зависимости; окружение не является доказательством дефекта.
4. Откройте внутренний PR с тестом и доказательством. Второй участник воспроизводит результат на закреплённом SHA.
5. Подтверждённое замечание отправьте в исходный PR #68 до 11.11.2026 23:59 по правилам организатора. Дайте ссылку на файл и строки исходного кода, приложите минимальные шаги и тест.

Приватные ссылки на тесты будут недоступны авторам чужой команды. Поэтому вставляйте минимальный тест/сценарий и существенный вывод прямо в исходное review. Публикация или предоставление доступа к рабочему репозиторию — отдельное решение.

Для pytest-тестов вне приложения после настройки зависимостей можно использовать:

```bash
PYTHONPATH="$PWD/source" .venv/bin/python -m pytest repro/ -v
```

Это форма команды; тестов воспроизведения пока нет. Каждая находка должна содержать собственную проверенную команду запуска и необходимые переменные окружения.
