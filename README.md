# Совместное ревью toyota-skyline — PR #68

Рабочее пространство команды **sensei-mcp**. Здесь храним проверки, воспроизведения и доказательства. Итоговые замечания отправляем GitHub Review в [исходный PR #68](https://github.com/markpolyak/lab_grader_web/pull/68).

## Главное правило: что куда писать

**Исследуем и проверяем вместе здесь; официальное ревью публикуем в исходном PR #68.** Это правило действует и для людей, и для агентов. Инструкции для агентов находятся в корневом [AGENTS.md](AGENTS.md).

Разделение нужно, чтобы вся команда проверяла одну и ту же сданную версию, могла обмениваться тестами и независимо воспроизводить находки, не меняя чужое решение. Этот репозиторий — рабочее пространство ревьюеров; его Issues и внутренние PR не заменяют GitHub Review, требуемое организатором.

| Что | Куда | Правило |
|---|---|---|
| Проверяемый код | `source/` | Читаем и запускаем; исходники и закреплённый SHA не меняем. |
| Области проверки, назначения, гипотезы и обсуждение | Issues этого репозитория | Непроверенные предположения явно обозначаем как гипотезы. |
| Тесты и скрипты воспроизведения | `repro/<идентификатор>/` | Прикладываем зависимости, условия и точную команду запуска; тесты храним вне `source/`. |
| Логи, скриншоты и результаты запусков | `evidence/<идентификатор>/` | Сохраняем только очищенные доказательства с SHA и командой запуска. |
| Подтверждённые дефекты и тексты замечаний | `findings/<идентификатор>.md` | Используем [шаблон](findings/TEMPLATE.md); указываем ожидаемый и фактический результат, требование и исходные строки. |
| Изменения наших тестов и материалов | Ветки `review/<область>` и внутренние PR здесь | Проверяем друг друга; не отправляем эти коммиты в ветку сдачи чужой команды. |
| Итоговые замечания для зачёта | GitHub Review в исходном PR #68 | Одно замечание на дефект, с самодостаточным доказательством. Публикуем по явному поручению пользователя. |
| Окружения, ключи и необработанные данные | Локально, в игнорируемых каталогах/файлах | Не коммитим секреты и реальные персональные данные. |

Для зачёта достаточно падающего теста **или** воспроизводимого сценария: шаги, ожидаемое и фактическое поведение. Ссылка на приватный файл сама по себе не даёт авторам возможности воспроизведения: минимальный тест/сценарий и существенный вывод включаем прямо в исходное review. Исправление чужого решения остаётся задачей его авторов.

Исходники не копируются в новую ветку сдачи. Подмодуль обеспечивает каждому участнику одинаковую версию. Не используйте `git submodule update --remote`.

## Начать работу

После создания репозитория на GitHub:

```bash
git clone --recurse-submodules https://github.com/colosss/sensei-review-toyota-skyline-pr68.git
cd sensei-review-toyota-skyline-pr68
python3 scripts/verify_baseline.py
git switch -c review/queue-registration
```

Если уже склонировали без подмодулей: `git submodule update --init --recursive`.

- `source/` — проверяемое приложение; [инструкция разработчика](source/docs/DEVELOPMENT.md), [описание проекта](source/docs/PROJECT_DESCRIPTION.md).
- `repro/` — наши тесты и скрипты воспроизведения.
- `findings/` — подтверждённые дефекты по шаблону `TEMPLATE.md`.
- `evidence/` — небольшие очищенные логи и скриншоты.
- `REVIEW_SCOPE.json` — SHA и ссылки для воспроизводимости.

Установка зависимостей и запуск приложения выполняются по документации `source/` в отдельном окружении. Реквизиты тестовых интеграций каждый участник настраивает локально. Этот репозиторий не содержит запущенного приложения или готовых результатов проверки.

## Как работаем командой

1. Создайте Issue в этом репозитории с областью проверки и назначьте ответственного. Гипотезу обозначайте явно.
2. Создайте ветку `review/<область>`, добавляйте свои файлы вне `source/`.
3. Зафиксируйте условия, команду запуска, ожидаемый результат, фактический результат и основание из требований. Для каждого теста укажите зависимости; окружение не является доказательством дефекта.
4. Откройте внутренний PR с тестом и доказательством. Второй участник воспроизводит результат на закреплённом SHA.
5. Подтверждённое замечание отправьте в исходный PR #68 до 11.11.2026 23:59 по правилам организатора. Дайте ссылку на файл и строки исходного кода, приложите минимальные шаги и тест.

Приватные ссылки на тесты будут недоступны авторам чужой команды. Поэтому вставляйте минимальный тест/сценарий и существенный вывод прямо в исходное review. Публикация или предоставление доступа к рабочему репозиторию — отдельное решение.

Для pytest-тестов вне приложения после настройки зависимостей можно использовать:

```bash
PYTHONPATH="$PWD/source" .venv/bin/python -m pytest repro/ -v
```

Это форма команды; тестов воспроизведения пока нет. Каждая находка должна содержать собственную проверенную команду запуска и необходимые переменные окружения.
