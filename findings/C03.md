## Замечание для исходного review

**Не используйте truthiness `outcome.passed` как вердикт CI.** В `grading/queue/ci.py:84-87,107-108` проверяется булева истинность поля, но реальный producer возвращает непустую строку вида `0/1 тестов пройдено` (`grading/grader.py:612-621`, передача в `grading/bulk.py:352-359`). Поэтому завершившийся с failure CI допускает студента в очередь. Это противоречит контракту `ensure_ci_passed` (`ci.py:41-54`: raises на любом non-passing outcome), и собственному тесту PR `tests/test_ci.py:70-87`. В тесте PR поле подменено bool, что скрывает несовместимость с настоящим producer.

Минимальный сценарий на этом SHA:
1. Один синтетический студент в ростере, индивидуальная ЛР с `ci: {jobs: ['test']}`, открытое занятие и действующая собственная student-session; ячейка оценки пустая.
2. GitHub возвращает один фиксированный latest SHA и для него check-run `name='test', status='completed', conclusion='failure'`, с непустым completed_at. Остальные необходимые ответы репозитория доступны. Используется реальный `queue_register → ensure_ci_passed → evaluate_student → LabGrader/GitHubClient`, подменён только HTTP transport GitHub и Sheets/window/config.
3. Выполнить `POST /courses/review-c03/groups/C03-G/labs/1/queue/register`.

Ожидается: отказ `400 CI_NOT_PASSED`, ожидающей строки нет. Факт: `200 {"position":1,"queue_size":1}`, строка `ждёт` создана, оценка записана как `x`. На свежем fixture с защищённой старой `v` и тем же красным текущим CI тоже 200 и допуск. Контроли: success допускается с `v`, pending отклоняется `409 CI_PENDING`.

Воздействие P1: обязательный барьер допуска фактически пропускает завершённые провальные проверки в обычном сценарии, не только при специальном обходе UI. Это не замечание о субъективной скорости GitHub.

## База, возражения, ограничения

`grading/queue/ci.py` новый в PR; bulk/grader со строковым результатом унаследованы и не изменены. Именно новый consumer неверно интерпретирует поле. Base diff проверен статически; функциональности очереди в базе нет, её поведение там не запускалось.

Возражение «проверяется только status updated» опровергается собственным docstring о verdict из passed и контрастом completed failure/pending/success. Fake transport соответствует полям, читаемым GitHubClient; реальные GitHub/Sheets, OAuth и browser в этом тесте не используются. Одна индивидуальная ЛР, без score/taskid/penalty. Восемь GET на попытку и унаследованные повторные SHA-чтения — отдельные наблюдения, не вторые находки этого пакета. Полное внешнее ТЗ организатора недоступно; основание — явный контракт нового guard.
