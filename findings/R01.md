## Отнесение к PR и ограничения

`StudentOutcome.passed` — строка для интерфейса, например `"0/1 тестов пройдено"`, а не bool (`grading/bulk.py:120`, `grading/grader.py:617`). У непустой строки истинное значение, поэтому `if not outcome.passed` не отклоняет провал. Аналогичная ошибочная проверка есть в ветке `rejected` на строках 84–86. В наших проверках использованы настоящие `LabGrader`, `_evaluate_ci_internal`, `evaluate_student` и HTTP-маршрут; подменён только клиент GitHub, возвращающий обычный check-run. Штатные `tests/test_ci.py` скрывают ошибку, подставляя в `passed` True/False.

Указанные строки и функциональность очереди добавлены этим PR; в базе `eef98bb373c71e9e4e7df4258e1fe5b4b4c5ac39` их нет. Это не унаследованная ошибка приложения.
Проверки используют только синтетические данные и fake-клиенты внешних сервисов. Google Sheets/GitHub production не изменялись. Проверка выполнена на Python 3.14.8; Docker/Python 3.12 отдельно не запускался, поскольку Docker daemon недоступен. Подтверждено конкретное состояние/ответ приложения; переносимость проверки на штатный Python 3.12 отдельно не заявляется.

Возможные возражения и результат проверки: независимая перепроверка человеком пока не проведена. Проверка ограничена зафиксированным SHA и синтетическими внешними клиентами; неподтверждённые и неоднозначные сценарии вынесены в CANDIDATES.md. Ручное наблюдение не подменяет проверку настоящих Google-сервисов.
