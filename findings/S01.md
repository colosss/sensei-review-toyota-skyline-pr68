## Самодостаточное замечание

**Не игнорируйте remove_slots[].labs, когда исходный slot не перечисляет labs.** Отсутствие labs означает все лабораторные. `_resolve_day` умеет вычитать только из явного списка; при current=None он делает continue. Материализация зависит от `queue_settings.all_lab_ids`, которого нет в штатных schedules и как обязательной предпосылки в документации.

Сценарий с manual-YAML для группы и ЛР1/ЛР3 курса:
1. Слот `id: guap-mon-2`, понедельник10:40–12:10, без ключа labs (то есть все).
2. На дату2026-11-09 добавить коррекцию:

```yaml
corrections:
  - id: cancel-lab3
    date: '2026-11-09'
    remove_slots:
      - slot_id: guap-mon-2
        labs: ['3']
```

3. В12:00 той даты (управляемое время, окно открыто) выполнить register собственного студента в ЛР1 и в ЛР3.

Ожидается ЛР1→200, ЛР3→403 QUEUE_CLOSED и нет waiting строки. Факт ЛР3→200 `{"position":1,"queue_size":1}`, строка ЛР3 ждёт. Если исходный слот явно перечисляет `labs: ['1','3']`, та же коррекция корректно закрывает ЛР3; без коррекции ЛР3 разрешена, после auto_close закрывается. P2: преподаватель отменяет конкретную защиту, но запись продолжает приниматься.

Основание: `docs/schedule-config.md:271-293` обещает частичную отмену при labs, иначе отмену всего слота; admin `CorrectionsDialog/index.jsx:224-229` формирует `remove_slots=[{slot_id,labs}]`. Это не выдуманный контракт поверх null; null/all — штатный случай поставленного расписания.

## База / возражения / ограничения

manual.py, schedule_window.py, docs/schedule-config.md и CorrectionsDialog добавлены PR. Base comparison статическое, поведение базы не запускалось.

Документированный пример remove_slots использует `id`, валидатор/UI — `slot_id`; здесь сознательно проверен supported UI-формат, который успешно разбирается. Несоответствие id/slot_id отдельная непроверенная до принятия гипотеза, не часть этой находки. Возражение «надо всегда задать all_lab_ids» не соответствует документации и штатным slots; при таком дополнительном обходном условии дефект не проявляется.

Проверен manual-YAML-путь допуска, не реальный GUAP import или весь browser editor. Системные часы не менялись. Реальные Sheets/GitHub и все варианты parity/corrections не проверены. Исправление не обязано быть конкретной материализацией списка — важно реально исключать отменённую ЛР.
