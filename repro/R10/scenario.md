# R10: сценарий

1. Откройте `/admin`, войдите преподавателем, в курсе выберите «Очередь на сегодня». В очереди два ожидающих.
2. Попробуйте вызвать первого, затем второго, не завершая первую защиту.
3. Фактически у таблицы только действия «Назад» и «Обновить»; вызова и списка текущих защит нет.
4. Обход через `queue/set-status` тоже не представляет вызов: допустимы только `сдал`, `не_сдал`, `нет`; data validation в Sheets также не содержит состояния вызванного.
5. Ожидается сохраняемое состояние двух параллельных вызовов без преждевременного проставления результата.

Ожидается: Преподаватель вызывает следующего, видит его среди вызванных, затем вызывает ещё одного и завершает каждую защиту независимо.

Фактически: На странице преподавателя только Назад и Обновить; действия вызова нет. Хранилище и API результата поддерживают лишь ожидание и конечные статусы, вызванный студент отдельно не представлен.
