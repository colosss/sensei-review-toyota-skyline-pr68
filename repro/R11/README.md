# R11: Добавьте ручное открытие записи и досрочное закрытие без изменения расписания

SHA: `20bea22cf4a1cbc19634a984883ff52764ce9d6d`.

Python 3.14.8; зависимости source/requirements-dev.txt; точные версии — evidence/baseline/python-dependencies.txt. Fake Sheets и GitHub, настоящие маршруты, grading и YAML. Системное время не меняется.

Синтетические данные: курс review, группа G1, студенты Alice/Bob/Carol Synthetic, лабораторные L1/L2. Условия конкретной находки:

1. Выберите курс с расписанием, в котором на сегодня для группы нет пары. Войдите преподавателем и откройте «Очередь на сегодня».
2. Попробуйте открыть запись для внештатного занятия: доступно только обновление списка; студент продолжает получать `403 QUEUE_CLOSED`.
3. На обычной открытой паре попробуйте досрочно закрыть новые записи: на экране также нет такого действия, решение об открытости берётся только из расписания.
4. Ожидаются ручные действия преподавателя, сохраняющие текущих ожидающих. Добавление/удаление слота или поправки в конфигурации изменяет запланированное расписание и не реализует отдельно оговорённое ручное открытие для занятия вне конфигурации.

Из корня репозитория после загрузки закреплённых подмодулей:

```bash
python3 scripts/verify_baseline.py
python3 -m venv .venv
.venv/bin/python -m pip install -r source/requirements-dev.txt
```

Значения ADMIN_LOGIN, ADMIN_PASSWORD, SECRET_KEY, GITHUB_TOKEN задаёт общий `repro/conftest.py`, только тестовыми строками. Настоящие credentials не нужны. При необходимости можно указать `REVIEW_SOURCE` как абсолютный путь другого чистого checkout того же SHA с тем же парсером.
